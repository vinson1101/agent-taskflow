# ATF 对外定位模板

这份文档只回答一个问题：

**现在对外介绍 ATF，应该怎么说，哪些话不要说。**

## 1. 当前推荐一句话

ATF 是：

**运行在 OpenClaw 之上的异步多-agent 协作控制层。**

如果需要更偏产品化的说法，统一使用：

**Agent Team Ops / Agent Collaboration Control Plane**

## 2. 当前推荐三句话版本

推荐模板：

1. ATF 不是独立 Agent 平台，而是多-agent 协作的协议、控制和运行保障层。
2. 它当前最适合内部、异步、非实时的多-agent 协作运营场景。
3. 它解决的是任务派发、状态跟踪、补漏 follow-up、统一唤醒和审计回写，而不是开放市场、支付或实时讨论。

## 3. 当前可直接复用的介绍段

ATF 是一套运行在 OpenClaw 上的异步多-agent 协作控制层。它把任务协议、trigger 扫描、action follow-up、launch dispatch 和审计回写收敛成统一控制面，让多个 agent 的任务交接、补漏和唤醒不再散落在聊天、日志和人工流程里。当前阶段，它优先服务内部协作控制面，而不是实时聊天、开放市场或支付优先产品。

## 4. 当前明确可以说的点

- 内部多-agent 协作控制面
- 异步任务协议与运行保障
- trigger / action / launch 三条控制链
- task repo + `ATF_DATA_DIR` 的双落地结构
- 非实时、可审计、可恢复、可逐步硬化

## 5. 当前不要说的点

下面这些表述当前阶段不要对外使用：

- 通用自治 agent 网络
- 开放市场优先
- 支付优先产品
- 已成熟的跨组织可信协作协议
- 实时多-agent 讨论平台
- 已有强一致 write-back 保证

## 6. 当前边界说明模板

推荐模板：

ATF 当前依赖 heartbeat / cron 驱动，不是实时事件系统；它已经适合内部异步协作控制面，但还没有完成签名身份、reviewer 权限治理、自动验收、争议处理，以及更重的跨节点通信和市场化闭环。

## 7. 对外问答模板

### 7.1 它是不是一个新的 Agent 平台？

不是。当前更准确的定位是多-agent 协作控制层，而不是独立平台。

### 7.2 它是不是实时聊天/会话系统？

不是。当前依赖 heartbeat / cron，更适合异步协作。

### 7.3 它是不是已经能做开放市场？

不是。当前更适合内部控制面；身份、治理和争议处理还没硬化到开放市场阶段。

### 7.4 它现在最值钱的点是什么？

不是“单个 agent 更聪明”，而是“多-agent 协作秩序更稳定、更可追踪、更可审计”。

## 8. 推荐用法

以后 README、产品文档、商业文档、演示介绍，优先复用下面两句：

- `ATF 是运行在 OpenClaw 之上的异步多-agent 协作控制层`
- `ATF 当前更适合 Agent Team Ops / Agent Collaboration Control Plane，而不是实时聊天、开放市场或支付优先产品`
