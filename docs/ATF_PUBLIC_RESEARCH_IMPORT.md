# U2：手工导入公开研究原件

这是一条**默认关闭的本机试点**，把经核准的完整公开研究产物或合成样件交给现有 ATF 任务和 DSH 评审链路。U2 首选 Cue 的完整公开研究交付；它不触发提供方、不读取或发送邮件、不访问 URL、不碰账号或凭据，也不新开监听。本合同不构成真实来源已验收的证据。普通邮件摘要、通知正文、截图和截取片段不是完整交付。

## 信任边界

- 操作人按既有 standalone 规则使用独有的私有根目录，手动创建模式 0700 的 `public-research-inbox/`。只放获准使用的完整文本与其清单，不放任何私人公司、个人或投资资料。
- 启用 `ATF_PUBLIC_RESEARCH_IMPORT=1` 后，**先由受信任的本机操作者**在交互终端独立核对来源、原件完整性、复制与交给指定验收者的许可，再确认终端显示的任务、来源、版本、哈希、验收标准和专用会话指纹。公开链接本身不是许可证；不要用模型推测许可。命令拒绝非 TTY 和清单中自填的许可标记。
- 这是本机文件信任模型，不是身份/权限服务。同一 OS 账号里能修改文件或控制终端的程序具有该账号的权限；因此不要把批准目录或批准命令开放给下载器、Agent 或其他账号，也不要脚本化批准。ATF 保存私有的、绑定准确选择与专用验收会话指纹的批准收据，不保存原件正文或凭据在收据中。无受信任操作者则不导入。

## 清单

使用私有 inbox 内的两个文件名（不接受 URL、目录、符号链接或外部路径）。清单是最多 4096 字节 JSON；产物是最大 10000 字节的完整 UTF-8 `.md` 或 `.txt` 文件。给出原始字节的 SHA-256，不做换行标准化。示例字段：

```json
{
  "source_kind": "synthetic",
  "source_id": "fixture-research",
  "source_revision": 1,
  "source_url": "https://example.invalid/research/fixture-research",
  "content_kind": "complete_research",
  "artifact_sha256": "<64 位小写十六进制>",
  "reviewer": "已登记的专用 DSH reviewer",
  "criterion": "写明验收条件（单行）"
}
```

`synthetic` 固定使用示例域名与逐字一致的 ID；`cue-public` 的 `source_url` 字段是逻辑引用 `cue-public:research/<source_id>`，不是网页或邮件定位符。操作人以不含账号、邮件 ID 等敏感信息的本地标识命名同一交付，并只提取获准的完整研究正文，不带邮件信头、线程、发件人、邮箱链接等传输元数据。逻辑引用只在本机保存，DSH 只收到批准的研究文本、验收标准及任务关联字段，不收到来源引用。操作人需检查正文与验收标准也没有夹带邮件定位信息或私人数据。可选但不作为验收前提的 `grok-public` 格式仅接受形如 `https://grok.com/share/<source_id>` 的无参数约定，不证明该链接已公开、支持版本或已接通。来源版本是大于零的整数，并映射到该任务的评审版本。完整性的业务核对由审批者承担，ATF 只验证输入范围、字节、批准和绑定，不推断摘要是不是全文。

## 操作与恢复

1. 创建该来源的专用 ATF 任务，确认已登记并启用合规的专用验收人。
2. 在人工控制的 TTY 执行 `atf dsh-review public-approve <task-id> manifest.json report.md`。按提示独立核对后键入精确确认短语；不确认不会导入。批准仅写模式 0600 的收据，不改变任务，不派发。
3. 执行 `atf dsh-review public-import <task-id> manifest.json report.md`。再次核对同一作用域和字节后，将原件与来源证据写入既有任务，在现有 ATF 事件信箱排队。导入记为 `source_state: imported`，`dispatch_state: pending` 表示尚未发送，不等于评审或通过。
4. 若需要 DSH 评审，由操作人另行用导入返回的完整事件 ID 执行 `atf event dispatch <event-id>`。不带 ID 的派发、低频对账或已有事件监听都会跳过该手工事件。派发前会再次核对原批准收据和专用会话指纹。随后沿既有 `dsh-review settle` / `verify` 验收。此 U2 试点不允许用通用交接命令变更收件人：批准仅覆盖原验收人和专用会话。

重复同一批准与导入是幂等的。每个独立来源只属于自己的 canonical 任务；相同来源版本若改变文件、哈希、来源或批准绑定，拒绝覆盖。崩溃若发生于原件与来源已入任务但事件还未落地，按完全相同的已批准输入重放导入，不重开任务或重发。不同内容须是同一来源、同一个未结案任务上的新版本，且单独审批；已经关闭的任务不会被导入重新开启。裸 `dsh-review submit` 不能绕过已导入任务的来源合同。

`npm run atf:dsh:public-research:test` 使用合成原件和本机模拟 DSH 验证上述边界，不是实际 Cue 或真实 DSH 接入证据。
