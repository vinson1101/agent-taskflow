## 2. 代码合并（与激活完全分开）

1. 复核 PR #1 只落隔离能力，保留默认 OpenClaw 路径；确认仓库允许的合并方法、分支保护／规则集、要求的独立审核和精确提交的检查。缺任何授权或必需审核则停，不改规则或用管理员绕过。
2. 若获准合并，先合 #1。优先用仓库允许且保留原 head 祖先关系的方法；读回新 `main` 提交、树和 CI。不能保留祖先关系时（如强制 squash/rebase），从新 `main` 构造只含原 #1→#2 增量的审查分支或按仓库流程整理 #2；不强推 `main`。
3. 再让 #2 指向新的 `main`，确认 PR 差异只有 U2/补充验证与文档，没有重复包含 #1 或遗漏基线。以更新后的 #2 head/合并目标重新取得 CI 与必要审查，读回最终 `main`。CI 应至少覆盖 Node 22/24、既有五组 smoke、U0 独立运行、DSH hardening/模拟集成/模拟交接、合成 U2 导入和发布包文件清单检查（见候选 `.github/workflows/ci.yml`）。
4. 只有另外明确版本与分发渠道后，才考虑 tag/GitHub Release/包发布；主线合并和 GitHub Release 都不会自动安装、启动或迁移。正式制品应引用精确主线 SHA，注明默认关闭及实测边界。若工作流实际带自动部署功能或目的不明，先停确认，不因预案改工作流。

## 3. 激活门槛与数据保护

- **默认不激活。** 保持原 OpenClaw 服务、调度、数据目录与责任不变。独立模式只用新的 0700 私有根目录、专用已授权测试会话和既有 loopback relay；不新增监听、账号或凭据。U2 默认关闭，仅受信操作员临时启用 `ATF_PUBLIC_RESEARCH_IMPORT=1`。TTY 精确批准只写收据；导入进原单并标为待派发，只有操作员指定完整事件 ID 才能派发。批处理／对账不会自动发出 U2；批准还绑定原验收人和专用会话，不能通过普通交接改变收件人。
- 单独批准的长期运行、生产或迁移前，先确定数据管辖者、哪些目录和配置为权威、当前事实时间与恢复目标，记录源与目标版本、守护进程与唯一写入者，列出未结 intent／事件／义务以及外部 relay 账。没有批准就只演练隔离快照；不碰真实任务、凭据、工作区或服务。
- **快照不要边写边拷。** 在获准的维护窗口停止新派发和导入，待单写者静止后，以只读清单盘点任务、事件、去重/派发意图、义务、审批/审计（包含权限及关联关系）；核定 `ATF_TASKS_DIR`、`ATF_DATA_DIR` 和独立根目录布局。保护每个文件字节、必要 mode/owner 与一致时间点。默认排除凭据、外部服务令牌、大段会话和无授权私人原件；若历史证据确需备份则另定已批准的受保护存储与保留期。清单仅内部保存，不发普通日志／GitHub。
- 在**无实际 relay 凭据、本机访问受限且与现场写入隔离的副本**做恢复演练：核文件哈希、目录权限和读回；抽查原任务 ID、产物 hash/version、未完成义务与当前回执归属。若涉及真实迁移，确认完整恢复、独立验收与回切边界，不能把同机副本当异机恢复。只允许单点切换，禁止旧、新两边同时写或同时派发。若需保持含路径的派发身份，在独立环境恢复到同一绝对路径布局，不在现场覆盖。2026-11-15 同机合成演练复核 19 个文件哈希，另起 CLI 读回任务、事件和义务一致，重查已发 stub 事件未产生第二次派发；没有验证异机或生产恢复。
- **隔离实测**：北京时 2026-11-15 15:05:42，按候选树 `5492030b` 在同机对纯合成数据做了恢复演练：先改名保留原隔离根，再将归档还原到相同绝对路径；19 个文件的 SHA 一致，新的 CLI 进程读回任务、事件和义务无差异；再次处理已派发的 stub 事件未新增派发。不证明异机解密恢复、真实 relay 故障恢复或生产备份。不同根目录预检若因路径绑定无法完整验收，可在隔离环境按原绝对路径恢复，但须先保留原目录、保证停写并隔绝 relay。
- 放行后也只开放已批准的负载。异常、路径越界、批准或身份不匹配、重复派发、原单版本错误、回执缺失、审批绕过、旧链路回归，立即停止扩大试点，保全证据。

## 4. 回退与不重发原则

| 现场 | 允许步骤 | 禁止 |
| --- | --- | --- |
| 只合了代码，试点默认关闭 | 不启动；必要时以新 revert PR 反转受影响提交，先撤依赖层 U2 再撤 U1，复跑 CI、读回主线 | force-push 历史；以改 Git 代替现场核查 |
| 隔离试点启动或导入过 | 停止试点的新写入/派发，保留隔离根和当下账本；关闭 U2 opt-in。核对原事件、产物版、意图、请求 ID、relay task ID+专用会话及本机状态；如需验证历史恢复，用另一个互不写入的隔离根 | 用不识别新评审门槛的旧版本写入试点数据；删除意图或重建新事件 ID 逃避对账；把回退说成取消对侧已运行任务 |
| 明确派发前被拦，且无任何 intent | 修正隔离预检后，仅在原许可内用同一个完整事件 ID 显式尝试 | 批量扫出 U2、用普通交接改变经批准的接收者 |
| 已有 intent，承诺响应丢失／结果不明 | 按原事件 ID 只读对账，用原请求和专用会话寻找唯一可归属回执；无匹配、超限、截断或冲突一律待人工查证。恢复到老快照前后都保留**更新**的 intent 与外部已知证据 | 查不到就 POST；盲目复活队列；清空 dedupe／已结义务；自动补投或只靠本地旧快照重启 worker |
| 若将来获准切换过生产 | 停新路径写者；按获准回切计划评估代码/数据兼容性、按订单对账冻结差异，决策后仅恢复原单写者与原配置；先读回现状和获准的最小验证 | 直接覆盖现场存储、丢弃切换后记录、让旧版（尚无验收闸门）writer 指向新版试点数据，或在对账前恢复定时派发 |

保留新版试点根目录作为隔离、不可派发的证据；代码回退不等于可用旧 writer 打开新版数据，也不代表对侧取消。无法确定已发送与否时，始终按原 ID 对账。

**记录放行/停止结果**：候选与实际提交、CI URL、已通过/未通过的门槛、备份与恢复证据时间、对账状态、下一责任人。未验生产、外部自动投递、真实 Hermes/A2A 时如实标为未验，不补造确认。
